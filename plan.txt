dGaitMate Demo Build Plan
========================

PROJECT CONTEXT
---------------
GaitMate is a hackathon prototype for an ankle biosensor sticker/monitor. The demo app is a web dashboard that shows ankle ligament strain, exercise guidance, and fall tracking. The real product would use live hardware + mobile app data. This demo uses a local CSV file as the data source and a lightweight Python backend to expose that CSV as JSON.

This is a feature demo, not a production medical application. Prioritize reliability, clear UI, and demo readiness over perfect architecture.

STACK
-----
Frontend:
- Plain HTML/CSS/JavaScript OR Vite + vanilla JavaScript
- Tailwind may be used if already configured, but do not block progress on Tailwind setup
- No React required unless the existing project already uses it
- Frontend consumes backend JSON endpoints with fetch()

Backend:
- Python 3
- Flask
- flask-cors
- pandas
- CSV file as demo database

Data:
- CSV file: Biosensor Data - FINAL Color Coded Strain Scale.csv
- Place a copy at: backend/data/biosensor-data.csv
- The CSV contains randomized biosensor data for ATFL, CFL, and PTFL ligament strain metrics.

IMPORTANT PROJECT RULES FOR CODEX
---------------------------------
1. Do not reorganize the project without being explicitly asked.
2. Do not delete uploaded mockup files, images, CSVs, or existing assets.
3. Do not introduce Supabase, Firebase, Sheety, SQLite, authentication, Docker, or a production database.
4. Keep backend and frontend separate.
5. Keep file names simple and lowercase where possible.
6. Use relative paths that work locally.
7. The app should run locally with two commands: one for backend, one for frontend.
8. The backend must read from the CSV and return JSON.
9. The frontend must not hardcode sensor values once API endpoints exist.
10. This is a demo. Make the simplest thing that looks polished and works.

BACKEND OVERVIEW
----------------
backend/app.py
- Creates the Flask app
- Enables CORS for local frontend development
- Registers routes from routes/sensor_routes.py
- Exposes a simple health check at GET /api/health

backend/services/csv_loader.py
- Loads backend/data/biosensor-data.csv with pandas
- Cleans column names if needed
- Converts rows to dictionaries
- Provides helpers:
  - get_all_rows()
  - get_latest_row()
  - get_row_by_time(time_value)
  - get_ligament_metrics(row)

backend/services/risk_engine.py
- Contains the five-level ligament risk algorithm
- Inputs:
  - max_strain
  - gradient
  - variability
- Outputs:
  - level 1-5
  - label
  - color hex
  - short advice

Risk levels:
1. Low Risk / Green
2. Low-Medium Risk / Green-Yellow
3. Moderate Risk / Yellow
4. Elevated Risk / Orange
5. High Risk / Red

Threshold logic:
- High Risk if max strain >= 8 OR gradient >= 4 OR variability >= 1.5
- Elevated Risk if max strain >= 6 OR gradient >= 3 OR variability >= 1.0
- Moderate Risk if max strain >= 4 OR gradient >= 2 OR variability >= 0.5
- Low-Medium Risk if max strain >= 2 OR gradient >= 1 OR variability >= 0.25
- Otherwise Low Risk

backend/routes/sensor_routes.py
Required endpoints:
- GET /api/health
- GET /api/sensor/all
- GET /api/sensor/latest
- GET /api/sensor/time/<time_value>
- GET /api/sensor/ligaments/latest
- GET /api/risk/latest

Expected /api/sensor/ligaments/latest response shape:
{
  "time": 49,
  "ligaments": {
    "ATFL": {
      "average_strain": 0,
      "max_strain": 0,
      "gradient": 0,
      "variability": 0,
      "risk": {
        "level": 1,
        "label": "Low Risk",
        "color": "#2a8a5f",
        "advice": "Within healthy range."
      }
    },
    "CFL": { ... },
    "PTFL": { ... }
  },
  "overall": {
    "level": 1,
    "score": 18,
    "label": "Healthy",
    "color": "#2a8a5f"
  }
}

FRONTEND OVERVIEW
-----------------
frontend/index.html
- Landing page
- Three navigation cards:
  - Track Sprain -> sprain.html
  - Current Exercises -> exercises.html
  - Fall Tracking -> falls.html

frontend/sprain.html
- Main feature page
- Shows ankle image
- Shows ATFL, CFL, PTFL cards
- Pulls latest data from GET /api/sensor/ligaments/latest
- Colors each ligament card based on backend risk output
- Updates the overall strain slider

frontend/exercises.html
- Exercise page based on UI mockup
- Can stay mostly static for the demo
- May include a fake live strain widget that optionally reads latest overall risk

frontend/falls.html
- Fall tracking page based on UI mockup
- Can stay mostly static for the demo
- Optional: show a mock table of fall events

frontend/js/api.js
- Central place for fetch calls
- Base URL: http://127.0.0.1:5000/api
- Exports:
  - getHealth()
  - getLatestSensorData()
  - getLatestLigamentData()
  - getLatestRisk()

frontend/js/risk.js
- Optional frontend mirror of backend risk logic
- Useful fallback only
- Backend remains the source of truth for current values

frontend/js/sprain.js
- Calls getLatestLigamentData()
- Updates DOM elements on sprain.html
- Handles loading and error states

frontend/css/styles.css
- Shared design system
- Colors based on mockups:
  - dark text: #1f3a44
  - teal: #2f6f8f
  - green: #2a8a5f
  - yellow: #d9a32a
  - orange: #e08a4a
  - red: #d65a4a
  - background: #eef3f3
- Keep UI visually close to Claude mockups.

CSV COLUMN MAPPING
------------------
The CSV has these important columns:
- Time
- ATFL-1, ATFL-2, ATFL-3
- CFL-1, CFL-2, CFL-3
- PTFL-1, PTFL-2, PTFL-3
- ATFL Average Strain
- ATFL Max Strain
- ATFL Gradient
- ATFL Variability
- CFL Average Strain
- CFL Max Strain
- CFL Gradient
- CFL Variability
- PTFL Average Strain
- PTFL Max Strain
- PTFL Gradient
- PTFL Variability

The first unnamed column may contain labels like Green. Treat it as optional metadata and do not rely on it.

SETUP COMMANDS
--------------
Backend setup:
cd backend
python -m venv .venv
source .venv/bin/activate   # Mac/Linux
pip install -r requirements.txt
python app.py

Backend should run at:
http://127.0.0.1:5000

Frontend setup option A, simple static server:
cd frontend
python -m http.server 5173

Frontend should run at:
http://127.0.0.1:5173

Frontend setup option B, if using Vite:
npm create vite@latest frontend -- --template vanilla
cd frontend
npm install
npm run dev

Only use Vite if the project is already configured or the user asks for it. Otherwise use plain HTML/JS.

IMPLEMENTATION ORDER
--------------------
1. Create the folder structure exactly as listed.
2. Copy the CSV into backend/data/biosensor-data.csv.
3. Copy ankle-ligaments.png into frontend/assets/ankle-ligaments.png.
4. Build backend first:
   - app.py
   - requirements.txt
   - services/csv_loader.py
   - services/risk_engine.py
   - routes/sensor_routes.py
5. Test backend endpoints in browser.
6. Build frontend pages.
7. Connect sprain.html to /api/sensor/ligaments/latest.
8. Keep exercises.html and falls.html static unless there is time.
9. Polish visual styling.
10. Do a full demo run.

DEMO SUCCESS CRITERIA
---------------------
- Landing page opens.
- User can navigate to Sprain Tracking.
- Sprain Tracking loads real CSV-backed data.
- ATFL/CFL/PTFL cards show values and correct colors.
- Overall strain slider moves based on the calculated risk.
- Exercises page opens and looks polished.
- Falls page opens and looks polished.
- No dependency on Supabase, internet APIs, or external database services.
